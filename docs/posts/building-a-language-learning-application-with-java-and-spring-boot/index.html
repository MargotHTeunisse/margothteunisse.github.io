Building a Language Learning App with Java and Spring Boot

Building a Language Learning App with Java and Spring Boot
Building a Language Learning App with Java and Spring Boot

When I was just starting to learn Python, I got the idea to use it to build a language learning application. The idea was simple: pick a word from a vocabulary list, ask the user to provide the translated word, and have the program check if the user is correct. To test the application, I used a short list of Finnish words, as I had had an interest in learning the language.

As it turns out, I would extensively use this program in my language learning journey. What I liked about it was that I could use my personal vocabulary list, and I didn’t need to put in any extra effort. Whenever I updated my vocabulary list with a new word, I could immediately use that. I also experimented with other features. The most important of these was a save function, as my vocabulary grew from a couple hundred to a couple thousand.

In the years since, I’ve been continuing to learn Finnish, yet my LangLearner application has grown somewhat neglected. That’s where this project comes in.

Goals

My goal for this project is to rebuild my LangLearner application from scratch, while sticking true to the spirit of the original program. While I originally used Python, for this new version I’ve chosen to use Java. It’s a language that I’ve been wanting to use more, and I think it is more natively suited for building applications than Python.

I’ve also been wanting to dip my toes into the Spring framework. I think LangLearner will be well-suited for that, as the appliciation itself is relatively simple, but at the same time it requires both a database and a user interface.

My goals are therefore as follows:

  • Build a domain in Java to pull pairs of words (‘flash cards’) from a deck, and check these against user input.
  • Have this domain comply with the Spring framework.
  • Build a database which can store custom vocabulary lists based on .txt files.
  • Implement a save/load function to deal with long vocabulary lists.
  • Build a simple user interface.

Methods

For this project I’m following domain-driven design (DDD), which is an approach where a domain model is at the center of the software. To ensure that my domain model is robust, I’m also applying test-driven design (TDD): writing failing tests first, and writing implementation to make the tests pass.

I’m writing my application in Java, as its object-oriented nature synergizes well with domain-driven design. I’m also using IntelliJ IDEA to write and execute my code.

Finally, in the spirit of agile development, I want to divide this project into manageable chunks, where I have a viable application at the end of each one. Even as a solo developer, that helps my sanity, and it has the added bonus of keeping these blog posts at a manageable level.

The code for my project is available on my Github. As a disclaimer, I will say that at the point of writing, I’ve already completed the first three parts of the project: constructing a console application, converting this application to Spring Boot, and using Spring Boot to construct a RESTful API. Therefore, my version history on GitHub might deviate from the order in which I’ve written these posts.

Except where explicitly specified, generative AI was not used for this project.
